# Red-team, 2026-11-11

Scope: why no desk-officer brief reached main between 2026-09-05 and
2026-11-11, why nobody was told, and what else in the publish path could fail
quietly. Evidence is from the Actions API (last 100 runs), the job logs, the
open pull requests and the claude.ai scheduled tasks, read on 2026-11-11.

## Findings

### R1. GitHub starts this repository's scheduled runs 7 to 10 hours late (root cause)
The `17 6 * * *` producer started at 14:39, 14:15, 12:59, 13:24, 16:17, 14:53
and 14:22 UTC on 2026-11-05..11. The "hourly" live map and Ukraine jobs ran
about three times a day. Every step that assumed a wall-clock time missed:

- the claude.ai routine (06:45 Chicago, 12:45Z) ran before the data existed
  and recorded SOURCE_NOT_READY;
- the dead-man (14:30Z) fired before compose could have run, so it failed
  every day whether or not the pipeline was healthy;
- the render and Pushover catch-up crons (11:15-13:30Z) were over before any
  brief existed.

The comment in `daily-brief.yml` said off-peak minutes "drift far less". They
do not, for this repository.

**Fixed:** the producer has eight cron entries and a gate
(`readiness.should_run`); the first firing after 06:10Z without a manifest for
the day builds. Compose, render and delivery are chained or dispatched, never
timed. The dead-man judges Chicago local time when it happens to run.
**To confirm after merge:** producer start times over the following days.

### R2. The Actions composer has no credential
`compose-brief.yml` failed on every run with "ANTHROPIC_API_KEY or
CLAUDE_CODE_OAUTH_TOKEN ... is required". PR #68 (2026-10-12) had the fix and
was never merged.

**Fixed in code:** either secret is accepted; with neither, the run skips with
a warning instead of failing red daily. **Needs the owner:** add the secret.

### R3. The routine's briefs were stranded in pull requests
A claude.ai cloud session can only push a `claude/*` branch. The routine
prompt said "commit and push", which produced a pull request each time. 58
were open; 38 briefs (28 daily, 2 more inside mixed PRs, 8 weekly) existed
only there.

**Fixed:** `auto-merge-briefs.yml` lands a pull request that carries exactly
one valid brief. The 38 stranded briefs are restored in this change.
**Needs the owner (after merge):** update the two live routine prompts to
match `docs/ROUTINE-desk-officer.md`.

### R4. The routine read readiness from the Pages URL
The manifest is committed to main before the site deploys, and the deploy
sometimes stalls, so the URL returned 404 for a manifest that already existed.
Ten pull requests record exactly that ("readiness manifest 404").

**Fixed in the canonical prompt:** manifest and bundle are read from
`origin/main` in the checkout.

### R5. A stalled Pages deploy failed the whole producer run
Four deploys on 2026-11-10 sat in `syncing_files` until the action's 10-minute
timeout (608-609 s; healthy deploys take 19-60 s; the artifact is 280 MB). The
producer run was marked failed and compose, gated on the run's conclusion,
skipped the day.

**Fixed:** each deploy gives up after 5 minutes and retries once; compose
judges the producer's `build` job, not the run.

### R6. The only alert channel was dead, and the alerts were noise
Pushover answered "no active devices to send to" for the dead-man. Because the
dead-man also failed on healthy days (R1), a red run carried no information.
The October report marked Pushover "fixed" (F2); delivery validation was
fixed, the device registration was not checked.

**Fixed:** every alerting workflow also records a tracked issue
(`[pipeline-alert:<key>]`), which mentions the owner once and is closed
automatically on recovery. **Needs the owner:** register a device in Pushover.

### R7. Published tree on course for the 1 GB Pages limit
`dist/` was 708 MB and grew about 4 MB a day; nothing ever deleted from it.
The dated section pages are unlinked after seven days.

**Fixed:** `worldscope/dist_maintenance.py` keeps 60 days (708 MB to 336 MB on
the real tree). Verified with a link crawl before and after: no link broken by
pruning.

### R8. Broken links already on the site
106 internal links were broken before this change: 35 "Bundle" links to
bundles that never existed (weekly briefs and old dailies) and chart images
referenced by repository path, which resolved to `briefings/briefings/...`.

**Fixed:** the bundle link is rendered only when the bundle exists; repository
-relative chart paths are normalised. 28 remain, all references to image files
that were never committed. **Open.**

### R9. Credentials in routine prompts
The prompts of two disabled claude.ai scheduled tasks ("Worldscope morning
brief (daily 06:00 ET)" and "Worldscope weekly brief (Friday 16:00 ET)")
contain the Pushover application token and user key in plaintext. They are not
in this repository (checked with `git grep`). **Needs the owner:** rotate the
application token and delete the two tasks.

## The new auto-merge path, attacked

The routine reads the open web, so treat its pull request as hostile input.

| Attack | Outcome |
|---|---|
| PR edits the workflow or validator to approve itself | `pull_request_target` runs both from main; the PR is never checked out |
| PR adds a workflow, script or any non-brief file beside the brief | not merged: every file must match the brief patterns for one date |
| PR modifies or deletes an existing brief | not merged: every file must have status `added` |
| Path tricks in a file name (`..`, other directory, other extension) | rejected by anchored patterns; covered by tests |
| Shell injection through title, branch or file names | no PR field is interpolated into a shell line; the number is passed by env |
| Brief Markdown carrying script, event handlers, `javascript:` links, iframes | stripped by the renderer; probed on 2026-11-11 with all five, none survived |
| Fork PR | job requires the head repository to be this repository |
| Backdated or far-future brief used to rewrite the archive | not merged: date must be within two days, week within one |

Residual risk: a routine misled by something it read can still publish wrong
analysis in a correctly shaped brief. That was equally true when it was meant
to push to main; the confidence tags and source links are the control.
