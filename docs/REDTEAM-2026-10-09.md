# Worldscope red-team, 2026-10-09

Scope: the whole path from upstream source to Ian's phone. Method: read every
workflow, the run reports, the Actions history, the lake, and the code; then
ask of each link "how would I know if this silently stopped working?" The
answer, too often, was "you would not."

Findings are ranked by damage. Each one names the evidence and the fix that
shipped in this branch, or the decision Ian still has to make.

---

## F1. The desk-officer brief has not shipped since 2026-09-05 (critical)

**Evidence.** `briefings/*.md` ends at `2026-09-05.md`. The Actions history of
`daily-brief.yml` (cron `0 7 * * *`) shows actual start times of 11:03Z on
09-05, 11:26Z on 09-06, drifting to 12:00-15:24Z through October. GitHub
delays top-of-the-hour schedules under load; the drift here is 4-8 hours.
The Claude routine fires on a fixed clock (designed for 09:00Z) and, since the
2026-09-06 "Harden Worldscope automation delivery and readiness" commit,
refuses anything but a same-date manifest younger than 6 hours. Every day
since, the routine ran before the producer, found a 404, and stopped. The
09-05 brief, the last one, was itself composed from the 09-04 bundle via the
old silent fallback.

**Why it was invisible.** Both failure modes were quiet: before 09-06 the
routine silently used yesterday's data; after 09-06 it silently produced
nothing. Nothing compared "briefs expected" with "briefs produced."

**Fix shipped.** `daily-brief.yml` cron moved to `17 6 * * *` (off-peak
minute, UTC date already equal to the Chicago date). `readiness.py` now also
writes `status/daily/latest.json`. The routine must fire at **10:30Z (05:30
CT)** with a retry slot at **13:30Z**; that is a claude.ai setting Ian has to
change (see `docs/ROUTINE-desk-officer.md` for the corrected prompt).

**Decision for Ian.** The structural fix is to stop clock-coupling entirely:
run composition from a `workflow_run` trigger on "Daily briefing" success
(claude-code-action, API-billed) so it can never race. That trades the
subscription-billed Routine for metered API spend. Recommended if the brief
matters more than the billing model.

## F2. Pushover delivery is unreliable in three independent ways (critical)

1. `tail | sed | head -c 900` under `set -o pipefail` dies with SIGPIPE
   whenever a brief exceeds 900 bytes (runs 37966588232, 37662379561,
   37662563636 all failed exactly here). Fixed.
2. The picker used `ls -t`, i.e. file mtime, which in a fresh CI checkout is
   checkout time: the "newest" brief was arbitrary. Fixed: newest by the date
   in the filename, never older than two days.
3. The receipt commit did a bare `git push` against a branch four bots push
   to; lost pushes lost receipts. `.pushover-sent.json` has no daily entry
   after 2026-05-29. Fixed with the same rebase-retry loop the other jobs use.

## F3. The Ukraine theater maps have been dead since 2026-09-13 while the hourly job reports success (high)

**Evidence.** Run 37950234101 log: `No module named 'fiona'` (the hourly
workflow installs `requirements.txt`, not the `[ci]` extra that has fiona)
and `ValueError: operands could not be broadcast together with shapes
(200,300) (220,320)` in the compositor, swallowed by `run_section.py` as
"map emit failed (data still refreshed)". Green check, no maps, for 26 days.
This is the section built for Ian's friends and family on the ground.

**Fix shipped.** Workflow installs `.[ci]`; the raster shape bug is fixed;
a failed map emit now surfaces as an Actions error instead of a green check.

## F4. Six of 42 sources were dead or frozen for months and readiness still said "ready" (high)

| Source | Last good | Failure (verified live) | Status |
|---|---|---|---|
| acled | 2026-06-02 | OAuth password grant with refresh tokens; old flow returned no token | rewritten with retry/backoff; a real 200 needs `ACLED_EMAIL`/`ACLED_PASSWORD`, so the first CI run is the verification |
| reliefweb | 2026-06-02 | v1 decommissioned (410); v2 returns 403 for any unregistered `appname` since 2025-11-01 | ported to v2; **Ian must register an appname** (apidoc.reliefweb.int/parameters#appname) and set `RELIEFWEB_APPNAME` |
| promed | 2026-06-02 | the relaunched site has no public feed; alerts sit behind an account-gated client | section now reports `no_data` with the reason; a feed URL can be supplied via `PROMED_FEED_URL` |
| gdacs | 2026-08-12 | `MAP` now requires exactly one `eventtype` | switched to `EVENTS4APP` with per-type fallback |
| gdelt_regions | intermittent | GDELT DOC rate-limits to one request per 5 s per IP; 19 sequential calls overran the deadline | 50 s budget, two workers, partial results accepted |
| people, sanctions | 2026-05-25 | local-only 2.6 GB OpenSanctions corpus, never refreshed | unchanged: needs a CI-reachable corpus or a hosted mirror |

That is the conflict, humanitarian and disaster backbone, gone, while every
manifest reported `status: ready` because readiness only gates on
*pipeline stages*, not on *source freshness*.

**Fix shipped.** `readiness.py` adds a `degradation` block: a
`REQUIRED_SOURCES` set and `MAX_STALE_DAYS = 3`; any required source older
than that is named in `degraded_reasons`. It does not block (the bundle is
still real) but `check-daily` prints a warning per reason and the routine
is told to put the list in the brief header. Dead feeds (Reuters, RSSHub,
PredictIt) removed from adapters.

## F5. "Collect data across time" was structurally impossible: the lake holds 9 days (high)

**Evidence.** `records.ingested_at` spans 2026-09-30..2026-10-08.
`lake_maintenance.py` enforces an 85 MB ceiling (GitHub's 100 MB file limit)
by evicting the oldest days, so the documented `keep_days=120` is never
reached. `briefs`, `paper_bets`, `record_embeddings` tables are empty: the
self-grading "intelligence loop" in ARCHITECTURE.md section 6 has no fuel.
`upsert_record` overwrote `ingested_at` on conflict, so first-seen time was
lost even inside the window. The only long history is 864 MB of per-day
JSONL under `lake/sections/`, committed uncompressed, with no query layer.

**Fix shipped.** Archive-before-evict into monthly gzip JSONL partitions
under `lake/archive/`, a backfill from the per-day JSONL, first-seen
`ingested_at` preserved, and `worldscope/history.py` as the one query API
over live DB + archive (`python -m worldscope.history counts|search`).

**Decision for Ian.** The repo is near 1 GB and growing ~15 MB/day of
committed `dist/` and lake JSONL. ARCHITECTURE.md's own trigger ("approaches
~1 GB") has fired. Options, cheapest first: compress `lake/sections/**`
going forward; move archive partitions to GitHub Releases or a Hugging Face
dataset (the roadmap's item 2); or a separate archive repo.

## F6. Stored XSS on the public site (medium, but public)

LLM-synthesised text built from untrusted feed content was inserted into
`dist/` HTML unescaped (`sections/__init__.py` ~359), `html.escape` on hrefs
does not stop `javascript:` URLs, and the Markdown renderer passed raw HTML
through. A hostile headline in any of ~300 RSS feeds could run script on
`ihelfrich.github.io`. Fixed: synth text escaped, hrefs restricted to
http(s), conservative sanitiser on rendered Markdown.

## F7. No "god's-eye" view existed: every geo signal was a static PNG in one day's brief (gap)

ACLED, FIRMS, USGS, GDACS, Ukraine theater, VIP flights and weather alerts
all carry coordinates and all ended up as per-day PNGs or prose. Shipped:
`worldscope/godseye.py` builds static GeoJSON layers plus a self-contained
Leaflet page at `/live/`, refreshed hourly by `live-map.yml`, with a time
slider, per-layer toggles, a "forest" panel of cross-section signals, and
click-through to primary sources. Static files only; no key ever reaches the
browser, in keeping with the architecture's one hard rule.

## F8. Smaller findings (fix when touching the file)

- Sections pull in daemon threads with a deadline; a timed-out thread keeps
  running and can write late. Needs a cancellable HTTP session or a process
  pool.
- Duplicate fetches of the same upstream (USGS twice, Polymarket twice,
  CourtListener three times, FIRMS twice). A shared fetch cache per run would
  cut quota use and timeouts.
- `feedparser.parse(url)` has no socket timeout in four places.
- `record_date` contains garbage ('' through 2027-03-22); validate at ingest.
- Four workflows push to `main` with `-X theirs` rebases. It works, but a
  single "publish" job fed by artifacts would remove the race entirely.
- `README.md` described Phase 1 with one working section. Rewritten.
- Watchdog dead-man alerts on a Mac heartbeat that is unrelated to this
  pipeline's health. A dead-man on the *output* is the alert that would
  have caught F1 on day one. Shipped: `brief-deadman.yml` pushes one
  priority-1 alert at 14:30Z if `briefings/<today>.md` or the day's
  readiness manifest is missing on `main` (mute with the repo variable
  `BRIEF_DEADMAN_MUTE_UNTIL=YYYY-MM-DD`).

## What "best in the world at open sources" needs next, in order

1. **Close the loop on production, not just collection.** A dead-man check on
   the brief itself (F8, last bullet) and a weekly self-audit that diffs
   expected vs produced artifacts.
2. **Make time a first-class axis.** With `history.py` in place, the next
   step is per-entity timelines and change detection over months, not days;
   then feed `paper_bets`/`predictions` so calibration actually accrues.
3. **Live map v2.** Cross-day story identity, entity pins from
   `cross_section.json` placed by geocoding, and an "alert me when a watch
   area's 24h count crosses 2σ" static digest. The forest panel also shows
   that cross-section entity extraction lets generic tokens through
   ("President", "James", "New York"); a stoplist and a type-aware
   threshold belong in `analysis/cross_section.py`.
4. **Source breadth where it is thin.** Sub-Saharan Africa, South Asia and
   Latin America are covered almost entirely through GDELT; add 2-3 local
   outlets per region in `foreign_news.py`. Add OpenSky-based airfield watch
   for the VIP layer and Sentinel-2 revisit flags for named sites.
5. **Decide the hosting question (F5).** The git-as-database design was right
   at 100 MB and is wrong at 1 GB.
